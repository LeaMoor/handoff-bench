## Главное

**Claude Code каскад не снимает, защищает только ключ.** Дубли, Claude Code / Haiku в цикле (21
эпизод на клетку) / Opus в цикле (9):

| Кто выдаёт ключ | новый запуск | повторная доставка |
|---|---|---|
| K0 — никто | 100% / 95% / 100% | 100% / 95% / 100% |
| K1 — субагент сам | 48% / 57% / 22% | 71% / 57% / 44% |
| K2 — оркестратор в задании | 0 / 0 / 0 | 0 / 0 / 0 |
| K3 — система от номера поручения | 100% / 71% / — | 0 / 0 / — |
| K4 — система по смыслу платежа | 0 / 0 / 0 | 0 / 0 / 0 |
| K5 — система закрепляет первый запрос | 0 / 0 / — | 0 / 0 / — |

Картина та же, что в нашем цикле. Ключ субагента в обоих сбоях вместе: Claude Code 25 из 42
(60%, 95%-интервал 44–73%), Haiku в цикле 24 из 42 (57%, 42–71%) — одно и то же. K3 ломается при
новом запуске (новое поручение — новый ключ). K2 держит, потому что повтор делает стенд тем же
заданием: Opus вписал ключ в задание во всех 42 эпизодах, субагент передал его дословно.

**Дубль — всегда «оплачено».** Где списали дважды, Claude Code ответил «оплачено» в 87 из 88
эпизодов (в цикле — во всех): он видит отчёт последнего субагента «успешно». Где дубля нет, он
чаще честно говорит «не знаю»: 82% против 64% у Haiku и 67% у Opus в цикле, «оплачено» — 16%
(счёт в банке остаётся открытым, и он не подтверждает оплату).

**Цена и лимиты.** ~36 тыс. токенов промпта на эпизод (29 тыс. из кэша), 3,6 ответа, ~42 с.
Оценка Claude Code «сколько стоило бы по API» — $15 за 252 эпизода; на подписке не списывается,
на OpenRouter за субагента — копейки. Недельное окно Pro за прогон выросло с 80% до 91%,
пятичасовое за 216 эпизодов после продолжения — до 70% (вместе с остальной работой на аккаунте).

## Выписка с ключом (60–63)

Ключ придумывает субагент, выписка показывает его оркестратору, повтор оркестратор решает сам;
никто не просит передавать ключ. 84 эпизода, invalid нет; сравнение — Haiku, DeepSeek и GLM в
нашем цикле на тех же мирах (60 — `hidden-v2`, 61 — `hidden-v3`, 62–63 — `code-key`).

**Opus ключ почти не передаёт, но и не дублирует.** Когда оркестратор снова поручает тот же счёт
после того, как первый субагент заплатил со своим ключом, ключ в новом задании:

| | Claude Code (Opus) | Haiku | DeepSeek | GLM |
|---|---|---|---|---|
| передал ключ | 3 из 18 | 7 из 27 | 22 из 34 | 21 из 37 |
| дубли: калибровка «после оплаты» (61) | 0% | 0% | 5% | 24% |
| дубли: главный блок, списание прошло (63) | 0% | 0% | 5% | 38% |

Opus защищает не ключ, а осторожность: в главном блоке он снова поручает тот же счёт в 29%
эпизодов (DeepSeek и GLM — 90%) и во всех 21 отвечает «не знаю». Так же ведёт себя Haiku. DeepSeek
и GLM поручают оплату снова, и тогда спасает только переданный ключ — передают его чаще, но не
всегда. Обратная сторона осторожности: в главном блоке, где списание не прошло (62), Opus честно
отвечает «не знаю» в 17 из 21 вместо того, чтобы оплатить (GLM оплатил во всех 21).

**Поправка к старой метрике.** `code_key.py` считал «поручил снова» по любому второму поручению —
в шаблоне 2 это обычно законная оплата второго счёта. Отсюда прежние 17/48, 19/60, 4/33
(results/2026-11-20). Если считать только повторы по тому же счёту, передача у моделей в цикле
выше: DeepSeek 65%, GLM 57%, Haiku 26% (`focal_key.py`). Вывод «ключ через трассу доходит не
всегда» стоит; цифры в `main` надо поправить отдельно.
